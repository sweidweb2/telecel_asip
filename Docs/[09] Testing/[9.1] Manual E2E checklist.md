# ASIP manual E2E checklist

Full-site pass for public pages and the admin panel. Grounded in current product behaviour (not stale RFQ notes). Automated Playwright specs in `e2e/` cover a subset of these journeys; this list is the complete manual pass.

---

## How to use

1. Copy this file or print a run log. Tick `- [ ]` for **Pass**. For Fail / N/A, leave the box empty and write **Fail** or **N/A** plus a note after the item.
2. Run against one environment at a time (local / staging). Record it in the run log.
3. Repeat locale-sensitive items in **English** (`/en`) and **French** (`/fr`) where the item says so. Do not triplicate every line for three viewports — do a dedicated responsive pass in section 0.3, then re-check only pages you change.
4. After flipping **Applications open** in Settings, wait up to **60 seconds** or hard-refresh. Public settings are cached for about a minute. (Newsletter is phase 1 hidden — no public toggle.)
5. Public forms need a working Cloudflare Turnstile widget. If the widget is missing, treat form submits as blocked (N/A for happy path, still check validation).
6. Product facts in the next section are marked **✅** when confirmed against the latest code. Manual test items stay `- [ ]` until you pass them on a run.

## Current product facts (do not file as bugs)

These are intentional today. ✅ = confirmed in the current codebase. Do not raise defects unless the product spec has changed.

- ✅ **No password-reset Server Action.** Login has a **Forgot password?** dialog that only shows `CONTACT.email` (`info@telecelgroup.com`) so users can email the team — no self-serve reset.
- ✅ **No outbound email or CRM.** Apply, Register Interest, Contact, and Newsletter writes go to the database only. Admins read them in the dashboard.
- ✅ **No honeypot** on public forms. Spam control is Turnstile + in-memory rate limit (5 per IP / 3 per email per hour, per process — not shared across serverless instances).
- ✅ **Apply / Register Interest require a signed-in account** (any role, typically viewer). Anonymous visitors see a sign-in / create-account gate; Server Actions reject logged-out submits.
- ✅ **Apply and Register Interest are mutually gated** by `open_applications`. When closed, only `/register-interest` is live (`/apply` redirects there and rejects Apply submits). When open, only `/apply` is live (`/register-interest` redirects there and rejects lead submits). The toggle also changes navbar/footer CTAs, the open banner, and intake SEO (`noindex` + sitemap).
- ✅ **Public signup always creates a viewer.** Elevated roles only via admin Users CRUD (`app_metadata.app_role`).
- ✅ **Leads are not converted** into Applications when Apply opens. Separate tables; invite manually.
- ✅ **No CMS `review` status and no scheduled publish.** Blogs/cohorts/events/stories are `draft` or `published`. Startups are `draft` / `active` / `inactive`.
- ✅ **No in-app backup restore.** Recovery copy points at Supabase PITR.
- ✅ **Editor role exists** in the database enum and user-list filter, but create/edit user forms always assign **admin**. An `editor` profile is treated like a viewer (redirected off `/dashboard`).
- ✅ **Events have no public marketing page** even when published.
- ✅ **Evidence is admin-only.** It never lists on the public site.
- ✅ **Home founder spotlight is not wired** to CMS startups.
- ✅ **Impact page metrics strip is not wired** (home impact numbers can still show when tagged `homepage_module_02`).
- ✅ **FAQ answers about “are applications open?” are static copy**, not live from Settings.
- ✅ **Alumni** is HOLD: reachable, in the navbar, `noindex`.
- ✅ **Lab page removed** from public marketing (no nav link, no `/{locale}/lab` route, no embedded lab assets).
- ✅ **Terms and Privacy** describe the live product (accounts/viewers, signed-in intake, Contact, newsletter gate, Turnstile, cookies, CONTACT details) — not draft placeholders.
- ✅ **Footer social links may be empty** until channels are verified.
- ✅ **Newsletter signup is phase 1 hidden.** Insights has no public signup UI. Settings shows “Hidden — phase 1” and always saves `newsletter_signup_enabled = false`. Server still rejects signup if forced.
- ✅ **Create-user empty password** stores the default `"password"` (must still include a letter and a number — the default value does).

## 3. Auth

Routes: `/{locale}/login`, `/{locale}/signup`, unlocalized `/login`, `/signup`, `/register` (signup alias), `/auth/callback`.

Signup: name 2–80; password ≥ 8, must include a letter and a number; confirm must match. Login: email + password.

- [ ] Unauthenticated `/dashboard` or `/dashboard/blogs` → localized login with `?next=` pointing at the attempted path.
- [ ] After admin login, `next` sends you to that dashboard path.
- [ ] `?next=//evil.com` or `https://evil.com` is **ignored** → `/dashboard` (open-redirect guard: path must start with `/` and not `//`). Same on `/auth/callback`.
- [ ] Authenticated user opening `/en/login` or `/en/signup` → `/dashboard`.
- [ ] `/register` and `/signup` reach signup (not the marketing register-interest form).
- [ ] French login/signup show FR validation messages.
- [ ] Bad password / unknown email → mapped invalid-credentials toast (not a raw Supabase dump).
- [ ] Duplicate signup email → **An account with this email already exists.** Stay on signup.
- [ ] Weak password (no letter, no number, < 8) blocked client-side.
- [ ] Confirm password mismatch blocked.
- [ ] Successful **public** signup creates a **viewer** (not admin). Opening `/dashboard` redirects to marketing home.
- [ ] Email confirmation: if the project requires confirm-before-login, unconfirmed login shows the mapped “email not confirmed” toast. If instant session, user lands per callback. Record which mode this environment uses.
